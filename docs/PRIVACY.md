# AuditGate privacy policy

Last updated: 23 November 2026

AuditGate is two Forge apps: **AuditGate** for Jira and **AuditGate for Bitbucket**. This page explains what data each one handles. It applies to every version distributed by installation link or listed on the Atlassian Marketplace.

## Who we are

AuditGate is built and maintained by softalpha0 (GitHub: <https://github.com/softalpha0>). Contact: open an issue at <https://github.com/softalpha0/auditgate/issues>.

## AuditGate for Jira

### What it stores

When someone in your Jira site uses AuditGate, it stores, in Forge hosted storage:

- **Audit details** you enter: audit name, auditor name, Bitbucket workspace and repository names, the audited commit hash, and the list of files in scope.
- **Findings** from the report you upload: IDs, severities, titles, descriptions, recommendations, file paths and line numbers.
- **Status history** for each finding: the Atlassian account ID of the person who changed it, the time, the old and new status, and any note, such as the reason and approver for an accepted risk.
- **Re-review sign-offs**: the commit hash, the account ID of the person who signed off, the time and their note.
- **A signing secret**, generated by the app and kept in Forge's encrypted storage. It is used to sign the AuditGate data on each issue.

It also creates **Jira issues** for each finding. Each issue carries an issue property with the finding's ID, severity, status and files, the audit's repository, audited commit, files in scope and signed-off commits, and a signature.

The report file itself is not stored. AuditGate reads it, keeps the findings, and discards the file.

### Network access

None. AuditGate for Jira only talks to your Jira site through Atlassian's APIs. It has no analytics, no tracking and no third-party services.

## AuditGate for Bitbucket

### What it stores

For each repository where an admin connects it, in Forge's **encrypted** storage:

- The Jira site ID, the signing secret copied from Jira, and the **email address and API token** of the Atlassian account the admin chose.

The token is never shown again after saving and is never sent back to the browser.

### Network access

One host: `api.atlassian.com`, Atlassian's own API gateway. The app uses the saved API token to read the repository's AuditGate findings from your Jira site. It only needs the `read:jira-work` scope and never writes to Jira. It reads pull request and diff information from Bitbucket through Atlassian's APIs.

## Personal data

- Atlassian **account IDs**, in finding history and sign-offs (Jira app).
- One **email address**, for the account whose API token connects Bitbucket to Jira (Bitbucket app, encrypted).

Neither app stores names or other profile data. Jira shows names by looking up account IDs at display time.

## Where data is stored

All data stays on Atlassian's platform: in Forge hosted storage, in your Jira site and in your Bitbucket workspace. Data residency follows your site, as provided by Forge.

## Who can see it

People who can view the Jira project can see AuditGate's pages and panels for that project. The signing secret is shown only to project admins, on the Connect Bitbucket page. The Bitbucket settings are shown only to repository admins, without the token. AuditGate's developer cannot see your data.

## How long it is kept

Data is kept while the apps are installed. When an admin uninstalls an app, Forge deletes that app's stored data according to Atlassian's Forge data retention rules. Jira issues created by AuditGate remain in your Jira site until you delete them. To disconnect Bitbucket sooner, use **Disconnect** on the repository's AuditGate settings page and revoke the API token in your Atlassian account.

## Your rights

Because data stays in your Atlassian site, your admins control it. To have data removed, delete the relevant Jira issues, disconnect Bitbucket and uninstall the apps, or contact us at the address above.

## Changes

We will update this page if what AuditGate stores changes, and change the date at the top.
